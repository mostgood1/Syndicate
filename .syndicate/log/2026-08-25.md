  because the user asked "are you sure this is set correctly now?" instead of

  not assumed.
- **Trying to delete the merged branches from this session.** Both
  `git push --delete` and a raw GitHub API `DELETE` call were refused with an
  explicit proxy message (write-access-to-this-path not permitted). Retrying
  the identical operation a second time (at the user's request) reproduced the
  identical 403 — confirmed as a policy block, not a transient failure, so
  further retries were not attempted.
- **The all-venues dollar cap design's first test draft.** Setting the default
  to the SUM of the two per-venue numbers ($150) meant the combined cap could
  mathematically never bind ahead of either venue's own cap under plain
  defaults — the first version of
  `test_an_order_within_its_own_venues_cap_can_still_be_refused_account_wide`
  was testing an impossible scenario. Caught before commit; rewritten to use an
  explicit env override so the mechanism is actually exercised.
- **A ledger idempotency collision in a new test.** Fifteen `place_order` calls
  sharing the same default `position_key="p1"` across a venue collapsed to one
  write per venue (the ledger's idempotency key is
  `position_key+date+venue+...`), so a test meant to prove a 15th-order refusal
  was actually only exercising 2 recorded orders. Fixed by giving each order a
  unique `position_key`.
