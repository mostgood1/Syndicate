## [syndicate-8d] CORRECTION: my soccer projection numbers were inflated by the SAME window bug

The subagent's NCAAF finding above applies to soccer too, and it corrects
figures I reported earlier today and put in a commit message (`c1c4211a`).

`_attach_projections_over_window` (`layer2_shortlist.py:1999`) sums
`rows_considered`, `rows_with_projection` and `rows_with_true_probability`
across every date in the window, calling the per-sport attach on the SAME
unfiltered grid each time. For soccer that window is SEVEN dates:

    rows_by_league sum (merged, NOT summed)   20,132
    considered      (SUMMED over 7 dates)    140,924
    140,924 / 7                            = 20,132.0   <- exact

So the real grid is 20,132 rows and every absolute count I quoted was ~7x too
large. **The RATIOS survive** -- both numerator and denominator inflate together
-- so 17.8% coverage, ~75% unattributed and "the name join is ~6% of the loss"
all still hold. The absolute figures do not:

    unattributed bucket   106,450  ->  ~15,200
    player name misses      7,020  ->  ~1,000

`unmatched_match=51` is NOT uniformly scaled (51/7 is not integral): it is
date-dependent, so it cannot be divided out.

**I had the evidence and dismissed it.** I computed the `rows_by_league` sum as
20,132 while `considered` read 140,924, noticed they disagreed, and wrote it off
as "rows_by_league only covers a subset". It was the un-inflated count sitting
right next to the inflated one. Same shape as the standing rule about reading
the field you already have.

What is NOT affected: the missing counter at `soccer_projections.py:995` was
real and is now instrumented, and the name-join fallback is unchanged. The fix
is right; my sizing of the problem was 7x out.
