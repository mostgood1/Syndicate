### What was verified, with evidence

- **The dead-gate removal doesn't change simulation output for any
  reachable path**: 254→323 hockeysim/nhl tests pass across every run
  this session (last run this checkpoint: 323 passed, 60s). No test
  asserts on the removed fields' absence specifically, but every
  reachability/calibration test that WOULD catch an output change if the
  removal broke something still passes.
- **`penalties_per_60`/`blocks_per_60` truly had no consumption path**:
  read `engine.py:715-733` directly — `special_teams.committed_per_game`
  (a REAL, already-populated field) is what drives PP/PK segment
  generation; confirmed no team-level rate feeds the block roll anywhere
  (`p_block_ev/pk/pp_def` × `block_rate_index`, a per-shot-event
  probability model, no rate input at all). Not inferred from field
  names — read the actual math.
- **`predictions_{date}.csv`'s model columns are not circular**: read
  `adapters.py::build_game_prediction` directly — it only calls
  `simulate_from_period_lambdas` on `period_goal_lambdas`;
  `market_anchoring.py` is a separate opt-in path for the props pipeline
  only, confirmed by grep + read, not assumed from the earlier §7
  circularity note (which is about a genuinely different code path).
- **The production `/nhl/api/cards` route serves the same real artifact,
  unmodified**: confirmed via the payload's own `source_path` (points at
  `predictions_<date>.csv` on Render's disk), `hasArtifactData=True`,
  `using_sample_data=False` — checked, not assumed from the route name.
- **`lookahead_applied`'s actual meaning**: read `nba/cards.py`'s
  identical flag (`bool(resolved_date != requested_date)`), then confirmed
  against all 20 cached NHL responses that every `lookahead_applied=True`
  response has `resolved > requested` — a genuine off-day fallback, not a
  live/in-game adjustment. The FIRST version of this script's assumption
  (rejecting these rows as circular) was wrong; caught by checking the
  cached evidence before shipping, not after.
- **Stale-duplicate predictions files are real, not a backtest artifact**:
  confirmed with a plain `diff` that 4 of 5 local prediction files are
  byte-identical to an earlier date.
- **All work is committed and pushed**: `git status --porcelain` shows
  zero uncommitted files under `syndicate/`, `scripts/`, `tests/`, or
  `docs/ai_context/`/`docs/reports/` related to this lane. `git
  merge-base --is-ancestor <sha> HEAD` confirmed after every push this
  session (`5dd4a714`, `661a06cf`, `4fa6659d` all ancestors of the current
  `origin/main` tip).

  `lookahead_applied=True` outright (23 of 24 rows in the first test run)
  on the assumption the flag meant live/circular adjustment. Wrong —
  traced the actual flag semantics in `nba/cards.py` before shipping,

  payload (confirmed against several non-null-EV dates), prose or
  otherwise. `--source both` covers puck-line from local files instead.
