against the NEXT season's realised margins (no leakage), ~740 games per pair:

    2023->2024   SP+ r 0.442 resid 18.25  |  PPA r 0.348 resid 19.08
    2024->2025   SP+ r 0.506 resid 17.63  |  PPA r 0.372 resid 18.97

SP+ wins on both metrics in both independent pairs. `SP_RATING_SCALE = 10.0`
calibrated by sweeping the real slate, not derived.

**NCAAF RATINGS WERE LEAKED.** `/ppa/teams?year=S` is season-aggregate and
contains the games being predicted: r 0.663 vs 0.509 as-of over 558 games of
2024, 30% inflation. Fixed to aggregate `/ppa/games` over weeks < N.

**2026 DATA BUILT**, coverage-checked against the 94 FBS teams the wk1 slate
needs: roster 15,442 rows / 138 teams / 0 missing; coach continuity 138 / 0;
returning production 136 / 2 (North Dakota State + Sacramento State, FCS->FBS
transitions with no prior FBS production -- legitimate); transfers 3,288 / 0.

**FIVE OF SEVEN BUILDERS COULD NOT RUN.** Only roster and player_game_stats
loaded `.env`; the other five died on "Missing CFBD API key" from a normal

**TOTALS: MECHANISM IDENTIFIED.** total = drives x score% x pts/score, and the
decomposition is exhaustive:

    game            total   drives   score%   pts/score   TD share
    LOWEST           27.5    24.4    20.8%      5.43       60.7%
    HIGHEST          68.6    20.0    53.9%      6.35       83.8%

**Scoring rate is the carrier: 20.8% -> 53.9%, a 2.6x swing.** Drives move only
24.4 -> 19.8 (and DOWNWARD as totals rise, which is correct -- scoring drives
burn clock). Real CFB converts ~35-45%; both ends are wrong. TD share 60.7% ->
83.8% against a real ~55-60% is a second defect in the same place.

### BELIEVED, NOT VERIFIED

- That fixing scoring-rate compression fixes totals. The decomposition proves
  scoring rate CARRIES the spread; it does not prove damping it lands total SD
  at 3.46 without moving margins.

### DEAD ENDS -- three failed hypotheses on totals, all reasoned, none measured first

1. **Index clamp too narrow.** Widened [0.05,0.95] -> [-0.75,1.75]. Margins got
   WORSE (15.97 -> 15.27) and totals worse (7.51 -> 9.55). REVERTED.
2. **Yardage weight asymmetry** (`offense*3.0 - defense*2.2`). Swept to parity
   and beyond: total SD moved 7.45..7.83, and parity was WORSE. The refactor
   was kept (constants -> profile fields, NFL byte-identical) but does not fix.
3. **`scoring_environment` weight asymmetry** (`offense*0.18 - defense*0.08`,
   2.25x). Swept 0.18/0.08 down to 0.06/0.06 -- a 3x reduction moved total SD by
   **0.07 points**. REVERTED, including the `profile` parameter it threaded
   through `build_drive_priors`.

**Why all three failed the same way:** they damp INPUTS to a loop whose outputs
COMPOUND. `drive_success_probability` feeds four-down sequences, so a modest
prior change barely moves the converted scoring rate. Correlation among inputs
(the r=0.782 on rating-net-sum) identified what MOVES WITH totals, not what
CREATES them -- decomposition did.

### Two methodology bugs I introduced and then caught, before trusting a
### single calibration number — recorded so they are not rediscovered

1. **A tuple-sort tie artifact.** `sorted(zip(probs, outcomes))` sorts
   ties in predicted probability by OUTCOME as the secondary key. The
   `offset=0` synthetic threshold (line == the player's own rolling mean)
   produces a massive exact-p=0.5 tie cluster, so the naive sort silently
   split that cluster into an all-miss bucket followed by an all-hit
   bucket — a fake 0%-then-100% swing that read exactly like a severe
   calibration defect on the first run. Fixed: sort on probability only.
2. **A pooled-market denominator**, the exact trap `learnings.md`
   2026-08-13 already names. First version of section 2 pooled all 9
   markets into one set of deciles; different markets have structurally
   different probability distributions, so the pooled curve swung sign
   bucket to bucket with nothing a reader could act on. Fixed to report
   per-market, kept a pooled table only as an explicitly labeled
   "informational only" summary.
