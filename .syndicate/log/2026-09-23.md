## 2026-09-23 22:30Z (17:30 CDT) — the context-line false positive is FIXED in both liveness tools `[scheduled task archive-closed-lanes-0917, session 17fb7689, no lane]`

`C:\tmp\lane-archive-tools`. Both tools carried the same defect at the same choke point, so both
were fixed: `owner_liveness.py` (asked) and `wait_owner_idle.py` (the identical `slug in diff`
check, which would have reproduced the block on the next watcher run).

**The defect.** The uncommitted-edit check matched the slug against the WHOLE diff text. Lane blocks
are large, so every hunk carries its neighbours' `### slug — STATUS` headers as context, and a lane
nobody edited gets attributed another lane's edit.

**The fix.** A `changed_lines_only(diff)` helper keeps only `+`/`-` lines (excluding the `+++`/`---`
file headers and the `@@` hunk headers, whose trailing excerpt is also context). Applied once per
tool, at the point the diff text is stored — which is the choke point BOTH call sites in each tool
(fresh diffs and stale diffs) read from. It NARROWS the check: a real edit to a lane's block always
emits a `+` or `-` line carrying that slug.
