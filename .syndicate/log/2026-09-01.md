### [syndicate-8d] `#630` FIXED with merge-on-receive — landed `e78aee52`, deployed to web 23:38:56Z, **verification pending**

`/api/ops/artifacts/publish` now UNIONS an append-only artifact with what is on
disk instead of replacing it. Publishes become **commutative**: whoever
publishes last, the result holds both services' rows.

#### Verified BEFORE deploying, on the two real production snapshots

    exchange   5,840 -> 7,158      recovered EXACTLY 1,318
    sportsbook 49,194 (the max)

**1,318 is precisely the count the clobber destroyed.** Replaying against real
captured data rather than fixtures is what makes this evidence rather than a
unit test passing.

#### Design decisions that are load-bearing, each with a test

- **Existing file stays a BYTE PREFIX.** Not tidiness:
  `pull_streamed_artifact` fetches these families by **HTTP Range** from the
  worker's local size, so any edit before that offset splices two different
  files together on the worker. **Merging is what finally makes that
  append-only assumption TRUE** — until now the file could be replaced wholesale
  underneath it. `_is_append_only` is **imported, not restated**, so the merge
  set and the Range-pull set cannot drift.
- **Dedup on the WHOLE LINE**, never a parsed semantic key. A wrong schema key
  collapses two genuinely different observations — silent loss, the expensive
  direction. Whole-line identity can only collapse byte-identical rows, and it
  makes this idempotent (54,866 duplicates collapsed on the real replay), which
  matters because every publisher sends its complete file every cycle.
- **BOTH receive forms merge.** live-odds-worker is **pinned on `7e76478f`**
  (confirmed in preflight) and sends the ENVELOPE form; fixing only the streamed
  path would have left the clobber live for one of the two writers causing it.
- **Non-append-only families still REPLACE** — the dangerous direction. The
  `.state.json` sidecar in the same directory is a dict rewritten every flush.
  A test asserts `clv_openings/*.jsonl` still replaces, so the rule cannot
  degrade into "ends with .jsonl".
- **No cross-process lock, deliberately.** Races are self-healing: every
  publisher sends its COMPLETE file every cycle, so rows lost to an interleaved
  read-modify-write are re-offered on the next publish. A lock would narrow a
  window that already closes by itself.

#### Why `#488`'s existing guard did not catch this

`_publish_divergence_verdict` refuses a publish substantially SMALLER than what
is on disk from a different publisher. Here the incoming file was **LARGER**
(25MB→37MB) because the clobbering writer had its own big batch, so
`ratio >= threshold` returned "allowed" **silently**. A guard encoding an
assumption about HOW something fails is silent in the real failure mode. It is
now skipped for merged families — refusing would reject the very publish
carrying the other service's rows.
