## lane: ncaaf-live-resim-wire — `conditional_arsenal_source`, the last 0.0% field

**VERIFIED. It was a write-side omission in the roster artifact, not a missing input.**

`conditional_mix.py:99-101` sets `conditional_arsenal` and
`conditional_arsenal_source` together. `de_pitcher` (`roster_artifact.py:343`)
reads the `_source` back — it is already in the string-field list. Only
`ser_pitcher` never wrote it. So the value was set in memory, expected on load,
and absent from every artifact. Nothing raised and nothing logged: the dataclass
default is `""` (`models.py:325`), which makes a DROPPED field and an UNFED
field the same reading.

The serializer's own comment, fifteen lines above the omission, describes this
exact failure: *"a new field that is not added here survives in memory and
vanishes through the artifact -- and the worker reads artifacts."*

**The tell was in the report and I had it before I looked at the code.**
Production's 2026-09-07T16:27:40Z `sim_input_report` read 9/10 with
`conditional_arsenal` ITSELF fed and only its `_source` at 0.0%. A missing input
cannot produce that split — the two are set on the same line. A write-side drop
is the only shape that fits.

**Evidence — OFF != ON, not a reading of the diff.** With the serialize line
removed the field round-trips to `''`; with it, to `'statcast_conditional_mix'`.

**Scope: ONE field, not a family.** A `dataclasses.fields()` walk over both
profiles — 69 fields, each set to a distinctive value and round-tripped — finds
exactly **1 lost against the unfixed serializer and 0 against the fixed one**.

A first pass appeared to show **26** losses. All 26 were the probe's fault, and
none was reported as a bug: fields whose real key domain is `str`
(`{str(k): float(v)}` on both sides) or `int` (`_ser/_de_intkey_map`) were being
fed `PitchType` keys, and `conditional_arsenal` was fed a tuple where its
producer keys with `str(cell_key)`. Recording the near-miss because a 26-bug
report would have been confident, wrong, and expensive.

**Shipped:** `af70a5cd` on `origin/main` — the one-line fix plus
`tests/test_roster_artifact_roundtrip.py`, the `dataclasses.fields()` walk the
serializer is not. Confirmed a real guard: 2 failed pre-fix, 3 pass post-fix.
It deliberately does not parse the serializer source to learn key types (that
would re-break on refactor); each dict field is probed with every key shape the
module supports and counted lost only when none survives.

**NOT YET VERIFIED IN PRODUCTION.** The deploy is queued, not done —
refresh-worker was held by `segment-regrade-apply`. Held rather than forced,
which this log's own entry above supports: a holder's session id does not
resolve in `list_sessions` even when alive, so `3492626c` "not found" is not
evidence it is gone. Outstanding reading: the first `sim_input_report` after the
