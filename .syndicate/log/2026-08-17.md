## Tie-spread membership gap — found by the post-first-pitch run, fixed

Follow-on from the baseline armed this morning. The question was whether first
pitch reads as NOT COMPARABLE. **It did not. It read as a clean pass, and that
was wrong** — the morning's claim that the per-state guard protects first pitch
was too broad, and the run that was supposed to confirm it disproved it instead.

### What the 12:37 CDT run actually showed

One game live, 10 in Preview, against the all-Preview `baseline_2026-08-17.json`.
The probe reported `identicalContentSpread 86px unchanged (baselined)` on desktop
and `43px unchanged (baselined)` on mobile, exit 0. Both were **false passes**:

| width | reported | baseline's number came from | current's number came from | groups that actually moved |
|---|---|---|---|---|
| desktop | 86px "unchanged" | `u=49 n=3` | `u=49 n=2` | `u=45` 28 -> 41 |
| mobile | 43px "unchanged" | `u=45 n=3` | `u=53 n=3` | `u=53` 30->43, `u=49` 32->15, `u=45` 43->36 |

On mobile the check compared the 45-pair group's spread against the 53-pair
group's spread, called them equal, and passed — while **every** group that was
genuinely comparable had moved.

**The mechanism.** `_cmp_value` reduced the whole tie block to `worstGroupPx`, a
max over a set whose membership moves with the slate. A game going live leaves
the Preview pool, groups gain and lose members, and the max lands on a different
group while reading numerically identical. The per-state guard cannot see this:
both sides still say `Preview`.

**This is the dangerous direction.** A false alarm gets investigated; a false
pass is silent. Same family as the standing rule that unknown must not default
permissive, and it is the second time a scalar summary has outlived the thing it
summarised on this file.

### The fix

Comparison is now per GROUP, matched on card identity:

- `tieFloor` records `ids` per group, from a new `cardKey()` — `el.id ||
  data-game-pk || first href`. Verified present and unique on every card surface
  2026-08-17: mlb `game-card-824514`, nfl `game-2026_01_NE_SEA`, ncaaf
  `game-1_North_Carolina_TCU`, soccer `game-401879301`.
- A group is judged only when the same state, pair count **and the same cards**
  appear on both sides. Movement there fails.
- Same size but different cards, a changed member count, a group that appeared or
  vanished: reported as slate movement, never judged. Three cards at 45 pairs on
  one side need not be the same three games.
- **Nothing comparable is never a silent pass** — it prints NOT COMPARABLE and
  says NOTHING was checked.
- State is part of each group's key, so first pitch now stops anything matching
  rather than needing the separate state check (which is kept for pre-group
  baselines).

**A pre-identity baseline does not fail.** Matched on size alone, the check
cannot tell a layout change from a reshuffled slate, so it reports `MOVED ... but
NOT FAILED` and asks for a re-baseline. Failing there would manufacture exactly
the false alarms of 2026-08-16. The "unchanged" line carries the same caveat, so
a weaker match never reads as a full one.

### Verified

- The live 12:37 payload replayed through the new code now names what was
  hidden: desktop `Preview 45 pairs 28px -> 41px`, mobile `43px -> 36px`.
- `tests/test_ui_layout_probe.py`: **101 passed** (was 93). Eight new tests,
