occurrences that happened to be whole-file deletions.

unreachable. The fix is to gate on the staged BLOB rather than on name-status:
block when a staged blob equals `git ls-tree HEAD^ -- <path>`, or more generally
when the staged content drops lines that are in HEAD and in the worktree.

## UI probe settle — fixed so a plateau cannot report as a finished render

Follow-up to the re-run above, lane `ui-probe-settle-plateau`. No deploy — this
is dev tooling in nobody's request path.

### What was wrong

`_settle()` returned `settled: true` after **two consecutive equal fingerprints**
(800ms, its floor). That is a gate on the *absence* of change, and absence cannot
distinguish "the render finished" from "the render has not started" — they are
the same observation. This is `learnings.md` 2026-08-16, *"a wait loop must gate
on an AFFIRMATIVE success token, never on the absence of a failure string"*,
recurring in a render poll rather than a deploy waiter.

Replaying the old rule over a plateau-then-growth tape:

    old_settle([100,100,100,200,300,400,...]) -> settledMs 800, settled true,
                                                 finalFingerprint 100

It stops inside the plateau and reports the **pre-enrichment DOM as final** while
the render goes on to 400.

### What changed in `scripts/ui_layout_probe.py`

1. **The quiet window is wall-clock, not a poll count.** New `SETTLE_QUIET_MS =
   2400` — continuous stillness, so the floor is 2400ms rather than 800ms. The

## Desktop height model — it cannot fit, and now it says so

Lane `ui-probe-desktop-height-model`. Asked to make the desktop model fit. It

### Both opening hypotheses were wrong

Written into the lane before testing, then killed by measurement:

- **(b) two-column wrap** — dead as stated. The pair grid is **10 visible

### What actually drives desktop height: text wrap

Production MLB, 2026-08-16, one slate, one instant, 15 Preview cards. Cards with

| | desktop | mobile |
|---|---|---|
| u=45 (n=7) | 1092..1208 = **116px** | **81px** |
| u=49 (n=5) | 1106..1203 = **97px** | **40px** |

The summary grid is a wrapping flow, so a long team name or a 5-character price

`reliable` wants `residual <= 0.25 * explained`. A 116px floor therefore needs

fit, not find one.

**81px** and its floor is **81px** — the fit sits exactly on the noise floor. It
is reporting how text wraps, not a layout deviation. Mobile passes only because
its slope is ~62px/pair against desktop's ~16px, buying 743px of explained range
to hide the same noise behind. **This revises the earlier entry in this log:** the
"residual band ~80–105px" recorded there is the wrap floor, not layout signal.

same idea at both widths: *two cards with the same amount of data should be the
same height.*

- `floorPx` — worst height spread among cards with identical `u` in that state.
- `floorRatio`, `unfittable` — the best ratio ANY model in `u` could reach here.
- `atNoiseFloor` — the residual is at or under the floor.

- **UNFITTABLE** replaces the bare "UNRELIABLE … no layout signal here" and
  states the two numbers, so the claim is checkable and nobody tries to rescue
  it with `LAYOUT_RESIDUAL_BUDGET_PX`.

### The actual cause is the slate, not the statistic

| run | mlb units | mlb states | nfl units | ncaaf units |
|---|---|---|---|---|
| 1 | 41-57 | Live 1, Preview 14 | 3-3 | 16-16 |
| 2 | 33-57 | Live 1, Preview 14 | 3-3 | 16-16 |
| 3 | 41-57 | Live 1, Preview 14 | 3-3 | 16-16 |

MLB carries a live game and enriches continuously, so its content moves between
runs minutes apart. NFL and NCAAF are static and read **1.00x across three runs,
both widths, under both statistics**.

So the generalisation is not about which statistic to pick:
**the identical-content spread is exactly reproducible on a static slate and not
reproducible on a churning one.** Picking between statistics was the wrong axis;
neither can hold still while the content underneath it moves.

### What shipped anyway, and why it is not wasted

`tieFloor()` now returns **both** statistics and the row prints both whenever
they differ, so no information is lost whichever one is diffed. `unfittable` and
`atNoiseFloor` deliberately keep using `worstGroupPx`: a fit has to beat EVERY
tie group, so tracking the largest one must never make something read as
fittable when it is not. Only `_cmp_value` changed which number the comparison
diffs — a one-line revert if the recommendation below is taken.

### Recommendation, not taken unilaterally

**Revert the tracked statistic to `worstGroupPx`**: it measured more stable on
both MLB rows, and it is the same quantity the impossibility floor already uses,
so one number would mean one thing. Then treat MLB-during-a-live-slate as not
baselineable in any statistic, and baseline NFL/NCAAF, which are exact.

Left as decided until told otherwise.

## Reverted to worstGroupPx — and two false alarms it exposed

User decision. The tracked statistic is the worst tie group again, so the number
a row PRINTS and the number the comparison DIFFS are one quantity, identical to
the one the fit-impossibility floor uses. No deploy.

`worstGroupPx` is read first by `_cmp_value`, ahead of `spreadPx`: reports
written during the brief largest-group window carry `spreadPx` meaning something
else, and diffing those against a current report would compare two different
quantities and call the difference movement. Both eras carry `worstGroupPx` and
it means one thing in both — verified live by comparing a post-revert run against
a largest-group-era report: `identicalContentSpread unchanged`, correctly.

`largestGroupPx` is still emitted and printed when the two disagree, because
disagreement is informative: it says a small group is straddling the extremes.

### False alarm 1 — the row contradicted itself in consecutive clauses

mlb mobile printed **"AT ITS NOISE FLOOR (164px), so this is text wrap, not
layout deviation"** and then **failed the run** with "LAYOUT RESIDUAL OVER BUDGET
(164px > 150px)" on that same number. No model beats its own floor by
construction, so the budget was unmeetable and the harness would have sat
permanently red on a healthy board — the outcome `fitGroup`'s own comments argue
against. A residual at its floor is now reported and not failed.

### False alarm 2 — "content-independent" inferred from a flat slope

With mobile fixed, mlb **desktop** failed instead: `LAYOUT SPREAD OVER BUDGET
(313px > 150px) with content not driving height`. But identical-content cards
differed by only **70px** on that same reading — 243px of the 313px tracked the
33-57 pair range.

The branch inferred "content is not driving height" from a near-zero linear
slope. On desktop that inference is FALSE, and this log already established why:
the pair grid wraps, so content drives height non-linearly. A flat slope means
the LINE cannot see it, not that it is absent.

The budget is now applied to the content-CONTROLLED figure — cards carrying the
same data, how far apart are they — whenever tied cards exist. Where nothing
ties there is no control, so the raw spread remains the signal and still fails;
the row says which of the two it used. The tie floor is taken from the model's
OWN state, since a floor from a different state is not a control for this one.
