## 0. The MLB standard — and the thing that has to be said first

**`_game_card_mlb.html` is not what MLB users see.** `[measured + from-code]`

`blueprints/mlb.py:335` — `_render_cards_page` serves `shared/game_cards_board.html`
(→ `_game_card.html` → `_game_card_mlb.html`) **only when `?client=board`**. The
default `/mlb/cards` renders `mlb/cards.html` + **`mlb/cards_source.js`, 3,880
lines**, which re-implements the entire card in JavaScript — including its own
copy of the tab rail at `cards_source.js:1978-1982`. Confirmed live: `/mlb/cards`
loads `cards_source.js` + `cards_exact.css` and contains **zero**
`.cards-head-team-name` elements.

So the "MLB reference implementation" other sports were told to converge on is a
fallback nobody visits, and the real MLB experience is a renderer nothing else
can share. Every convergence claim in this audit has to be read against that.

### The spec, as actually served on `/mlb/cards` (desktop 1440)

- **Layout**: a horizontally-scrolling strip of 14 compact scoreboard cards
  (`.cards-strip-card`, 280 px each), then a stacked HR-targets rail below.
- **Card fields, in order**: state pill (`LIVE`/`PREVIEW`) · situational badge
  (`F1 YRFI`/`F1 NRFI`) · start time → `TEAM | R | H | E` header row → two team
  rows (logo, tricode, R/H/E) → live situation line (`Top 1 | Count 0-0 | 0 outs`)
  → market line (`TOTAL · ML · +12 playable`) → `Odds updated 8/14, 1:15 PM` →
  away starter + 3 ladder pills → home starter + 3 ladder pills.
- **Missing values render `-`** (E column on preview games). Consistent.
- **Type scale actually in use on one card: 22 distinct
  size/weight/line-height combinations** (27 on mobile). `[measured]`
- **Named classes, computed**: `.cards-mini-copy` 10px/400 ·
  `.cards-market-label` 10px/800 · `.cards-market-main` 12px/400 ·
  `.cards-market-sub` 10px/400 · `.cards-tab` **9px/800** ·
  `.cards-data-pair span` 10px/800 · `.cards-data-pair strong` 13px/700.
- **Color**: CSS custom properties, `--cards-*`, 19 declared in
  `mlb/cards_exact.css`. Values are correct and match every other sport's copy.
- **Tabs** (on the `?client=board` variant and inside `cards_source.js` alike):
  three, hardcoded — `overview` / `boxscore` / `props`, labelled Game / Box
  Score / Props. Rendered unconditionally; no data gate.
- **Empty state**: `.cards-empty-copy` with a written sentence naming the
  missing artifact. Good pattern, used consistently in the MLB template.
- **Loading / error state**: none. Server render, then a 30 s poll.
- `box-sizing: border-box` is applied globally on this page — **and this is the
  only cards page where that is true.** See §5.

**Where MLB is not the standard to copy**: 9px tab labels; 28 px tab touch
targets; 22 type combinations on one card; the widest card-height variance of
any sport (§5); no tabular figures (§4); and a 3,880-line JS renderer.

## 1. Component divergence — N copies, and the drift is measurable

**Templates.** `_game_card.html` is a 6-line dispatcher over three forks:

| variant | file | lines | used by |
|---|---|---|---|
| `mlb_main` | `_game_card_mlb.html` | 479 | MLB `?client=board` only |
| `ncaaf_main` | `_game_card_ncaaf.html` | 316 | NCAAF |
| default | `_game_card_generic.html` | 327 | NFL, soccer, NCAAB, NBA/NHL/WNBA board fallback |

Plus a fourth, `mlb/cards_source.js` (3,880 lines), and a fifth for WNBA/NBA
(`cards-parity.js` + `cards_source.js`). Same for the scoreboard strip:
`_scoreboard_strip{,_generic,_mlb,_soccer}.html`.

**Stylesheets — the drift is quantified.** `[measured]`

- `syndicate/static/mlb/board.js` is **byte-identical to the first 52 lines of
  `syndicate/static/shared/game_board.js`**. A pure copy with no behavioural
  difference — the cleanest possible example of the failure mode.
- `wnba/cards-parity.css` (3,878 lines) vs `nba/cards_source.css` (3,977 lines):
  **102 diff lines, ~97.4% identical**, and WNBA is a **strict subset** — it has
  nothing NBA lacks. The 99 missing lines are `.cards-live-lens-badge-row`,
  `.cards-live-lens-confidence` and its `--high`/`--med`/`--low` variants. NBA
  gained a live-lens confidence badge; WNBA renders that markup unstyled.

**Token duplication.** The `--cards-*` palette is declared **four times** —
`shared/app.css` (13), `mlb/cards_exact.css` (19), `nba/cards_source.css` (24),
`wnba/cards-parity.css` (24). The **values agree everywhere**, which is the good
news. The sets do not: `app.css` lacks `--cards-warm/danger/success` and all four
radii; `mlb/cards_exact.css` lacks `--cards-panel*`/`--cards-border*`.

**A shadow palette.** `shared/board_cards.css` uses three properties defined
**nowhere in the repo** — `--cards-surface-alt`, `--cards-text-muted`,
`--cards-text-strong` — across 9 declarations. All nine carry fallbacks, so
nothing breaks; but the fallbacks are Tailwind slate values (`#94a3b8`,
`#e2e8f0`, `#1c2230`) rather than the system's (`#93a9bc`, `#edf4fb`, `#0d1c2a`).
Nine rules on every board page are permanently outside the token system and will
not respond to a palette change. Contrast is fine (`#94a3b8` on `#1c2230` =
**6.25:1**, passes AA; the system equivalent is 7.19:1) — this is a consistency
defect, not an accessibility one.

**Shared JS.** `shared/game_board.js` is genuinely shared by NFL / NCAAF / NCAAB
/ soccer and stands down when a bespoke script is present
(`BESPOKE_CARDS_SCRIPT_SELECTOR`). That part of the architecture works.

## 2. Data contract

### Three-way markets: the tiles handle the draw, the probability bar does not

Soccer **does** get a draw tile — measured on `/soccer/epl/cards`, EPL Coventry @
Arsenal: `HOME WIN 77.3% · DRAW 14.0% · AWAY WIN 8.7% · TOTAL GOALS 3.24`. That
is correct and should be credited.

**But the same card renders a two-way probability bar reading `Home win 81.1%`.**
`[measured]` Two different home-win probabilities, ~4 points apart, on one card,
~250 px apart on screen. The bar is structurally two-sided —
`game_board_contract.py` emits only `away_pct`/`home_pct`, and the markup is
`.cards-prob-away` + `.cards-prob-home` with no third segment. There is **no
draw slot in any card template** (`grep draw` over `templates/shared/` and
`templates/soccer/`: zero hits). A three-way market cannot be expressed by that
component, so it renders a number that disagrees with the tiles above it.

### A fabricated 50/50

`game_board_contract.py:303-304` — when win probabilities are absent,
`away_pct` and `home_pct` **default to 50.0**. `[from-code]` A game with no model
renders a centred, confident-looking probability bar. This is the same defect
class as the model layer's `_fair_probability` 0.5 fallback: absent data
rendered as a coin flip rather than as absent.

### MLB-shaped slots on non-MLB sports

`_game_card_generic.html` gives soccer and NFL a `boxscore` panel and a
"Period odds and game lens" region. Measured on soccer: the game-lens panel
renders a large empty area, and the same projected-score sentence is repeated
**four times** on one card (summary, Full Game card, and twice under Top Plays).
NFL's `props` panel contains 2 `.cards-empty-copy` blocks at 349 chars — the tab
is present, the content is an empty-state string. `[measured]`

### Null handling is inconsistent across the three forks

`[from-code]` `_game_card_ncaaf.html` uses `'-'` in 11 places; `_game_card_generic.html`
in 2; `_game_card_mlb.html` **never** — it relies on Jinja's silent-undefined,
which renders empty. No template uses `—`, `N/A` or `--`. MLB's JS renderer uses
`-` consistently for R/H/E. So the same missing value shows as `-` on NCAAF, an
empty cell on the generic card, and `-` on MLB.

**A raw timestamp leaks to the UI**: NCAAF cards render
`KICKOFF 2026-08-29T16:00:00.000Z` unformatted. `[measured — see
ncaaf_tab_game_BLANK.png]`

### Team-name length

`[measured]` Desktop: 0 overflowing names on any sport (NFL longest
"New England Patriots", NCAAF "Jacksonville State", soccer "Coventry City").
**Mobile 390 is where it fails, and badly** — NFL cards do not reflow (see §5),
so names break mid-word: "New Engla nd Patrio ts", "Seattle Seaha wks",
"San Fran sco 49e rs". See `nfl_mobile.png`.

Soccer team names also render **blue and link-coloured** on the card head — the
generic template wraps them in `<a href>` when `game.away.href` exists and the
anchor is not restyled to `--cards-text`. MLB's names are white.

### One view model or many?

One contract exists — `game_board_contract.py` builds `shared_*` rows the generic
card reads. But MLB's primary page bypasses it entirely (JS renderer), WNBA/NBA
have their own, and NCAAF's fork reads different keys. So: **a shared view model
that three of the five renderers do not use.**

## 3. Tabs — the stated complaint, isolated

### Three different tab contracts

| contract | attribute | handler | sports |
|---|---|---|---|
| A | `data-tab-target` | `shared/game_board.js` | NFL, NCAAF, NCAAB, soccer |
| A′ | `data-tab-target` | `mlb/board.js` (byte-identical copy) + `cards_source.js` | MLB |
| B | `data-card-tab` + `data-card-target` | `wnba/cards-parity.js` | WNBA, NBA |

`shared/game_board.js` selects `.cards-tab[data-tab-target]` and therefore can
never match a WNBA/NBA tab. **WNBA's tabs do work** — verified with trusted
Playwright clicks, all three panels activate correctly and no console errors.
(An earlier synthetic-`el.click()` probe suggested otherwise; that result was
wrong and is retracted.)

### NCAAF: the default tab renders a blank card — CONFIRMED

`[measured, trusted click]` NCAAF tab targets are `game / context / details`.
Its panel ids are `identity / context / coverage / details`.

```
click "Team Context" -> active panel ['context'] , card height 485px
click "Details"      -> active panel ['details'] , card height 550px
click "Game"         -> active panel []          , card height 187px   <-- blank
```

`activateTab` toggles `is-active` on for `data-panel-id === 'game'`, which does
not exist, and off for everything else — so the card collapses to its header
strip with nothing below it. Evidence pair:
`ncaaf_tab_context_OK.png` / `ncaaf_tab_game_BLANK.png`.

The initial server render is fine (the template marks the `Game` tab and the
`identity` panel active together), so this only fires **after** a user visits any
other tab and comes back — which is the normal browsing motion. Panels
`identity` and `coverage` have no tab pointing at them and are unreachable by
click.

### Tab sets are hardcoded, never derived from data

`[from-code]` Four different sets across three templates: MLB
`overview/boxscore/props`; generic `game/boxscore/props` + conditional `panels`;
NCAAF `game/context/details`; WNBA `game/box/props`. Note MLB's first tab id is
`overview` where every other variant uses `game` — a gratuitous divergence in the
one place a shared handler has to agree.

Only one tab anywhere is conditional (`{% if game.panels %}` on the generic
card). Everything else renders whether or not there is content behind it —
measured on NFL, the `props` tab opens onto two empty-state blocks.

### State, focus, keyboard

- **Per-card DOM classes only.** Not in the URL, not persisted, not global.
  Switching sport is a full navigation, so nothing carries over — the "selected
  tab that doesn't exist in the new sport" failure cannot occur. `[from-code]`
- **But the 30 s poll destroys the selection.** Measured on NCAAF: selected
  `Details` → 40 s later the card is back on `Game`/`identity`. `[measured]`
  See §6.
- **ARIA is incomplete**: `aria-selected` is toggled on bare `<button>`s with no
  `role="tab"`, no `role="tablist"`, no `aria-controls`, no `tabpanel` roles. A
  screen reader gets three buttons, not a tab set.
- **No arrow-key navigation** (the WAI-ARIA tab pattern). The `keydown` handler
  only re-implements Enter/Space, which `<button>` already does natively — so
  every keyboard activation runs `activateTab` twice (idempotent, harmless).
- **Console errors on tab switch: zero**, every sport, both widths. `[measured]`

## 5. Card density and layout

### Height variance — MLB is the worst offender `[measured]`

| sport | desktop min→max | spread | mobile spread |
|---|---|---|---|
| **mlb** | 914 → 1235 | **321 px** | **796 px** |
| ncaaf | 498 → 558 | 60 px | 50 px |
| wnba | 1462 → 1476 | 14 px | 205 px |
| nfl | 1036 → 1050 | 14 px | 30 px |
| soccer | 949 (n=1) | 0 | 0 |

The reference implementation has a 321 px ragged grid; the sports that were told
to match it are tight. This inverts the assumption in the brief.

### Horizontal page overflow — root cause found, one line

**NFL, NCAAF and soccer scroll horizontally by exactly 28 px at every width.**
`[measured]` `documentElement.scrollWidth` 1468 vs `clientWidth` 1440. MLB and
WNBA: 1440 vs 1440, no overflow.

The cause is not layout, it is a missing reset:

| page | global `box-sizing` | overflow |
|---|---|---|
| mlb `/cards` | **border-box** | 0 px |
| wnba `/cards` | border-box | 0 px |
| nfl / ncaaf / soccer `/cards` | **content-box** | **28 px** |

On the content-box pages, `.standalone-app-header` computes `width: 1424px` +
16px padding each side → renders 1458 px, and every
`article.feature-game-card` computes `width: 1420px` + 13px padding → 1448 px,
inside a 1440 px viewport. `syndicate.html:8` already carries the comment
*"app.css has no global box-sizing reset; width:100% + padding elements…"* — so
this was known and patched in one template, and the standalone shell that serves
`/cards` for four sports never got it.

Visible in `soccer_desktop.png`: the `SOCCER` nav pill and the `AWAY WIN 8.7%`
tile are both clipped at the right edge.

### Mobile 390 — NFL and NCAAF do not reflow

`[measured]` NFL card heights are 1036–1050 desktop and 1949–1979 mobile — barely
2× on a viewport 3.7× narrower, because the cards stay in a horizontally
scrolling row ~250 px wide rather than stacking. The consequence is the mid-word
name breaking in §2. MLB stacks correctly (914→3620 px, a real reflow).

`nfl_mobile.png` also shows duplicated nav rows — `BETTING CARD`, `PICKS` and
`LIVE LENS` each render twice, once from the date-controls partial and once from
the module nav.

## 6. Live-update behaviour

`shared/game_board.js` polls its own URL every **30 s** and does
`current.innerHTML = fresh.innerHTML` on each swap container, guarded by
`if (current.innerHTML === fresh.innerHTML) return;`. `[from-code]`

The guard prevents churn on an unchanged slate — that part is right. When
content *has* changed, the whole container is destroyed and rebuilt, so all
client-side state is discarded. Measured on NCAAF: `Details` selected → 40 s
later the card is back on the server default. `[measured]`

This differs by sport, and the split matters:

- **NFL / NCAAF / NCAAB / soccer** — `game_board.js` swap. Tab selection lost
  every 30 s on any live slate.
- **MLB / NBA / WNBA / NHL** — bespoke scripts; `game_board.js` stands down via
  `BESPOKE_CARDS_SCRIPT_SELECTOR`.

**The two NCAAF defects compound**: a user clicks "Team Context", the poll throws
them back to "Game", and if they then click "Game" themselves the card goes
blank. The sport with the broken tab is also the sport that resets the tab.

## 8. Ranked fixes — most user-visible first

Each gets its own lane. None of this pass changed code.

1. **NCAAF `data-tab-target="game"` → `"identity"`** (or rename the panel). A
   one-word edit in `_game_card_ncaaf.html` that stops the default tab rendering
   a blank card. Also wire `coverage`, currently unreachable.
2. **Add a global `box-sizing: border-box` reset to the standalone shell.**
   Removes 28 px of horizontal scroll from NFL, NCAAF, NCAAB and soccer at every
   breakpoint. The comment in `syndicate.html:8` already diagnoses it.
3. **Make the mobile card grid stack on NFL/NCAAF.** Fixes the mid-word team-name
   breaking, which is the single ugliest thing in the screenshot set.
4. **Preserve tab selection across the 30 s poll.** Read the active
   `data-panel-id` per card before the swap and re-apply after — ~6 lines in
   `game_board.js`. Do this with (1), since NCAAF is where both bite.
5. **Give the probability bar a draw segment, and stop defaulting to 50/50.**
   Soccer currently shows two different home-win numbers on one card. An absent
   probability must render as absent, not as a centred bar
   (`game_board_contract.py:303-304`).
6. **One null placeholder, applied at the contract.** Pick `—`; `_safe_text`'s
   default is already `-`. Kill the empty-render path in the MLB template.
7. **Format the NCAAF kickoff timestamp.** Raw ISO in the UI.
8. **Delete `static/mlb/board.js`** — byte-identical to `shared/game_board.js`'s
   first 52 lines. Free, and it removes one fork from the count.
9. **Backport NBA's 99 live-lens-confidence lines into `wnba/cards-parity.css`**,
   or (better) do fix 11 and delete both.
10. **Define `--cards-surface-alt` / `--cards-text-muted` / `--cards-text-strong`**
    in the token source and drop the Tailwind-slate fallbacks.
11. **Add `font-variant-numeric: tabular-nums`** to the numeric card classes in
    `dense_cards.css` / `cards_exact.css` / `cards_source.css` / `cards-parity.css`.
12. **Raise mobile tab targets to 44 px** and MLB's tab label off 9px.
13. **Real ARIA on the tab set** — `role="tablist"`/`"tab"`/`"tabpanel"`,
    `aria-controls`, arrow-key navigation; drop the redundant Enter/Space handler.

## 9. Proposed consolidation — proposal only, not implemented

**The shape of the fix is one card component plus a sport config**, not eight
forks. What has to be true first:

**Step 0 — decide what MLB's card actually is.** Nothing else can be settled
while `_game_card_mlb.html` and `cards_source.js` are two implementations of one
card and only the JS one ships. Either the JS renderer becomes the standard (and
the template is deleted), or the template becomes the standard (and the JS
renderer is retired to `?client=source`). **This is a product decision and it
blocks the rest.** My read: retire the JS renderer — a 3,880-line client-side
card is the reason MLB's fixes never reach the other sports — but that is a
bigger job than this audit can scope, and it needs the user's call.

**Collapse these into one `_game_card.html`:**

- `_game_card_mlb.html` + `_game_card_generic.html` + `_game_card_ncaaf.html`
  → one template. The three differ in *which panels exist* and *what the tiles
  are called*, not in structure.
- `static/mlb/board.js` → delete (proven identical).
- `wnba/cards-parity.css` + `nba/cards_source.css` → one `basketball_cards.css`
  (97.4% identical today), or better, fold into `dense_cards.css`.
- `_scoreboard_strip_{mlb,soccer,generic}.html` → one, same treatment.
- One token file. Not four.

**What the sport config has to express** — everything currently forked:

```
market_shape      : two_way | three_way        # draw segment on the bar, tile count
period_labels     : {"1": "1st Inning", "q1": "Q1", "h1": "1st Half", ...}
tabs              : [{id, label, panel, required_field}]   # id == panel id, always
                                                           # omit the tab when
                                                           # required_field is absent
identity_fields   : probable_pitchers | starting_xi | depth_chart | none
score_columns     : ["R","H","E"] | ["G"] | ["PTS"] | []
box_score         : true | false               # NFL/soccer have none -- omit the tab
extra_slots       : [competition, leg, aggregate_score, red_cards]  # soccer
tile_labels       : {"home_win": "Home Win", ...}
null_placeholder  : "—"                        # one value, at the contract
```

The two rules that make this stick, both learned from what this audit found:

1. **A tab's `id` must equal its panel's `data-panel-id`, enforced in the
   config**, so NCAAF's mismatch becomes structurally impossible rather than a
   bug to be found again.
2. **A tab is rendered only when its `required_field` is present.** NFL's empty
   Props tab and soccer's blank game-lens region are both "MLB-shaped slot, no
   data" — configuration, not markup, should decide that.

Legitimate differences that must stay differences: soccer's draw and
competition/leg; MLB's probable pitchers and R/H/E; basketball's quarters;
NCAAF's coverage/publication tier. All of them fit the config above. **None of
them justify a second stylesheet.**
